可穿越体素体积云：UE5 落地要点

对应工程 GTL-Render-VoxelClouds（UE 5.8，C++ 加一个全局着色器模块，不改引擎）。本文按数据流顺序列出 Nubis³ 式体素云的每一步做法：三维体素建模数据、SDF 的距离变换和保守块压缩、噪声细节提升、SDF 跳空的光线步进、光照网格、按 200 m 拆分的两档分辨率与深度感知合成，并附关键常数、坑点和移植清单，可以直接对照源码搬进自己的项目。原理、讲座数字与复核见 Research.html。

1. 总览

核心思路：整片可飞越的云景是一张 512×512×64、每格 8 m 的稠密三维纹理（4096 m × 4096 m × 512 m，底面在海拔 200 m），所以隧道、云洞、悬垂都能直接表示。8 m 的轮廓在步进时被一张 128³ 的平铺噪声“侵蚀”到约 0.5 m 的细节。光线在云外按 SDF（到最近云的距离）大步跳过，在云内按随距离增大的步长采样；太阳光的大部分路径改查预计算的光照网格。

文件对应：云景生成和编码在 Source/CloudLab/Private/CLCloudField.cpp；渲染器在 Source/CloudLabShaders/Private/CLRender.cpp 和 Shaders/CloudLab.usf；每帧参数的组装和 UE 体积云对照在 CLCloudManager.cpp。

2. 云景数据（NVDF）

先在 CPU 上算一个有符号形状场 S（米，云内为负）：积云是若干椭球的平滑并集加表面位移，雷暴云带砧状顶，层云是带噪声边缘的平板；隧道和云洞用平滑最大值 SMax 从云里挖掉。然后写成每体素 4 字节的建模纹理：

通道内容写法
R 维度轮廓（profile）从云表面向内的梯度，0 在表面，1 在 40 m 深处pow(saturate(-S / 40), 0.7)
G 细节类型0 丝缕状（wispy）到 1 团簇状（billowy）每朵云一个值
B 密度缩放整朵云的浓淡着色器里取四次方
A 分区雷暴云标记，用于加密度、压暗和闪电0 / 255

同一份数据再生成一个 2.5D 包络版本：每列只保留最低和最高的云体素，加覆盖范围和边缘梯度（讲座中的包络法）。两套数据各有自己的 SDF，开关切换时整套替换，玩法查询也一起切换。

纹理格式大小
建模（每套）RGBA8，512×512×6464 MB
SDF R16（每套）G1632 MB
SDF BC1（保守 / 不保守，每套各一张）DXT1，0.5 字节/体素8 MB
SDF BC4 对数（每套）BC48 MB
噪声RGBA8，128³，带 MIP约 9.6 MB
光照网格G16R16F，256×256×328 MB
演示工程为了能切换对比，同时常驻所有格式和两套数据。实际项目只需要一套建模纹理加一种 SDF 编码：讲座的配置是建模三通道 BC6H（16.8 MB）加 BC1 SDF（8.4 MB），合计约 25 MB。建模纹理也可以直接压成 BC7 或 BC6H，本工程没有做。

3. SDF：距离变换与编码

3.1 精确距离变换

占据判定是“轮廓 > 0”。用 Felzenszwalb–Huttenlocher 的可分离平方距离变换，沿 X、Y、Z 各做一遍一维变换，分别求到最近云体素和到最近空体素的距离，再合成有符号距离：云外 (√d − 0.5) × 8 m，云内取负，钳到 −256 到 4096 m。一维变换要用 double，无穷大取 1e12，否则长空行会溢出。整张 1677 万体素的网格在 CPU 上约 0.2 秒（按 Z 层 ParallelFor）。

3.2 BC1 565 拆分编码

BC1 本来是颜色格式。讲座的做法是把一个 0–1 的标量拆进 R、G、B 三个通道，解码时按权重相加：

// CloudLab.usf · GetSdf
float u = dot(SdfBC1.SampleLevel(LinearClamp, uvw, 0).rgb, float3(1.0, 0.03529415, 0.00069204));
float sdf = -256 + u * (4096 + 256);

R 是粗值，G 补 R 的量化余数，B 再补 G 的余数。编码器对每个 4×4 块：端点 c1 取块内最小值向下取整到 565，c0 在最大值附近试 16 个候选；每个体素只能选“不大于真实值”的调色板项。

不同厂商的插值结果不一样，这一点决定了编码是否真的保守。CLCloudField.cpp 的 ChanUp 对每个通道取四种解码的最大值：理想浮点、AMD 的 ((64−w)a + wb + 32) >> 6、Intel 的 ((256−w)a + wb + 128) >> 8（公式来自 Fabian Giesen 的 GPU BCn decoding），以及按 RTX 3060 回读得到的 NVIDIA 公式（5 位通道 ((2a+b)·22) >> 3，6 位绿色通道有自己的舍入）。只按理想公式编码时，NVIDIA 硬件上有体素解码后比真实距离更大，光线会越过云的边缘。

3.3 BC4 对数映射

单通道，每块 8 个调色板值，按 u = ln(1 + (s+256)/64) / ln(1 + 4352/64) 映射，表面附近（s 小）的精度更高。同样按各厂商插值的上界选“不大于真实值”的项；NVIDIA 的偏差按回读结果取 0.0112·|e0−e1|/255 的余量。

编码大小越界纹素（编码器的解码模型下）平均低估
R162 B/体素0（向下取整）约 0.07 m
BC1 565 拆分，保守0.5 B/体素02.25 m
BC1 565 拆分，按最近值0.5 B/体素640 万—
BC4 对数，保守0.5 B/体素01.80 m

BC 数据由 CPU 编码后直接按块上传：PF_DXT1 / PF_BC4 的三维纹理，行距是 (512/4)×8 字节，层距是行距乘 512/4（见 CLRender.cpp 的 UploadVolumes）。

4. 细节提升

移植自讲座数据包里的 GetUprezzedVoxelCloudDensity。噪声纹理 128³ 平铺，每 100 m 一个周期，采样坐标是世界坐标（米）加风的偏移，所以细节锚定在世界里，相机移动时不滑动：

float3 np  = (P + WindM) * 0.01;                         // P：域内米坐标
float  mip = NoiseMipByDistance ? log2(1 + dist * 0.004) : 0;
float4 n   = NoiseTex.SampleLevel(LinearWrap, np, mip);
float wispy   = lerp(n.r, n.g, profile);
float billowy = lerp(n.b * 0.3, n.a * 0.3, pow(profile, 0.25));
float comp    = lerp(wispy, billowy, type);
// 150 m 内：噪声两次取绝对值折叠，得到更高一级的频率，50–150 m 渐变
float d = saturate((profile - comp) / (1 - comp));       // ValueErosion
float pds = pow(densityScale, 4);
d = pow(d * pds, lerp(0.3, 0.6, pds));

R/G 通道是低频和高频的丝缕噪声，B/A 是团簇噪声。数据包没有附许可证文件，本工程没有带它的噪声，而是用分层 Worley F1 生成替代品：丝缕通道对坐标做周期性扭曲，团簇通道取 1 − F1，每个通道拉伸到 0–1。

密度还乘了一个近处衰减 ValueRemap(dist, 4, 40, 0.25, 1)，避免相机贴脸时一片糊。讲座用的是 10–120 m；隧道半径只有 26 m，用那么长的过渡会让洞壁变成半透明的雾。

5. 光线步进

每条光线先和域的包围盒求交，再截到场景深度（转成沿光线的米数）。循环：

step = adaptive ? max(1, 0.08 * sqrt(t)) : 3 + 60 * t / 16384;   // 米
if (SdfSkip) { sdf = GetSdf(P); step = max(sdf, step); sample = sdf < 0; }
P += dir * jitter * step;      // 250 m 内每帧变化的抖动，之外固定
if (sample) { 密度 → 光照 → 累积 }
t += step;
// 结束条件：透射率 < 0.01、出域、到达场景深度，或循环次数到上限
  • SDF 的主要价值在步数预算内能采到远处的云。不限步数时，SDF 把循环次数降到 1/2 至 1/8，但耗时变化不大，因为云内采样数没变。步数上限 256 时，没有 SDF 的光线在半路就停了，远处的云直接消失（截图 09 / 10）。
  • 透射率低于 0.01 时停止，并把结果当作完全不透明（Col /= 1 − Tr，alpha = 1）。不这样做，HDR 太阳圆盘会从厚云后透出来。
  • 抖动：250 m 内每帧换一个哈希值（配合 TSR 时间累积），远处用固定值，避免远处闪烁。

6. 光照

6.1 光照网格

LightGridCS 对 256×256×32（每格 16 m）的每个格子，朝太阳走到域边界，累加 轮廓 × 密度缩放 × 步长（云外按 SDF 跳，步长不小于 16 m）；再竖直向上累加一遍作为天空方向。结果存进 RG16F。每帧只更新 4 层，8 帧扫完一遍；太阳方向变化、数据切换或首次构建时整张重算。

步进时，太阳透射 = 朝太阳方向 4 m 和 12 m 处两次直接采样（8 m 步长）+ 在 P + sunDir × 16 m 处查网格。近处两次直接采样保住小尺度的自阴影，网格提供远距离的云间阴影。对照项“10 次光照步进”是每个采样朝太阳走 10 步、每步 25.6 m，既贵，又看不到 256 m 以外的遮挡。

网格要对每个格子都算，不能只算云内的格子。洞壁附近的视线采样会在云内和云外的格子之间插值，云外格子如果是 0，洞壁会发亮。

7. 两档分辨率与合成

近层只步进 0–200 m，1/4 分辨率；远层从 200 m 开始，1/2 分辨率。两层分别输出预乘颜色和该像素的场景深度。镜头在云里时，近层几乎每条光线都在云内，所以给它最低的分辨率；远层的细节更小，分辨率高一档。

上采样（CompositePS）在低分辨率纹理上取 4×4 个邻点，权重是半径 1.5 个纹素的帐篷函数乘以深度相似度 exp(−30 × |z_i − z| / z)。只用 2×2 双线性时，抖动会显出 4×4 的网点；不按深度加权，飞机和地形边缘会漏出一圈云。最后以 One, InvSrcAlpha 混合进场景颜色。

8. 接入 UE 渲染管线

  • 入口：FWorldSceneViewExtension 的 PrePostProcessPass_RenderThread，在后处理（含 TSR 和色调映射）之前写场景颜色，所以云会参与时间抗锯齿和曝光。着色器目录在模块启动时用 AddShaderSourceDirectoryMapping("/CloudLab", 工程/Shaders) 映射。着色器模块的 Build.cs 要加 Renderer 的 Private 和 Internal 头文件路径。
  • 坐标：着色器里一律用“域内米坐标”：(translated world − DomainMinTW) / 100，其中 DomainMinTW = 域最小角（cm）+ View.PreViewTranslation。这样大世界坐标（LWC）下也不丢精度。
  • 资源：所有三维纹理在渲染线程用 RHICmdList.CreateTexture 创建一次，每帧 RegisterExternalTexture 进 RDG；光照网格是带 UAV 的外部纹理，跨帧保留。
  • 通道：光照网格和两层步进是计算着色器（8×8 线程组），合成是全屏像素着色器。
  • 计时：在每个通道之间插入 EndRenderQuery（RQT_AbsoluteTime），四组查询轮转，读三帧前的结果，避免等待 GPU。
  • 游戏线程到渲染线程：每帧把开关、太阳、风、闪电打包成一个结构体，用 ENQUEUE_RENDER_COMMAND 拷过去；数据上传也走渲染命令。

9. UE 体积云对照路线

把同一张建模纹理和噪声做成瞬态体积纹理（UVolumeTexture::CreateTransient，B8G8R8A8，注意 RGBA 到 BGRA 的通道顺序），交给一个 Volume 域、勾选 used_with_volumetric_cloud 的材质，材质里的 Custom 节点做同样的细节提升。UVolumetricCloudComponent 的层底设为 0.2 km、层厚 0.512 km、追踪距离 6 km。

  • 消光接在 SubsurfaceColor（UE 的云材质约定），单位是每米，和自研渲染器的 0.05 一致。
  • 必须加 Volumetric Advanced Material Output 节点，设相位 0.6 / −0.2 / 混合 0.3、多重散射 2 个八度（贡献、遮挡、偏心各 0.5）。不加时 UE 只算单次散射，背光的云是一片平灰，看起来像组件坏了。
  • 改了云材质后第一次运行时，着色器要后台编译一阵，期间云不显示。
  • 差别：UE 的组件没有 SDF 跳空，按层高分配采样，并做低分辨率的时间重建。远看相近，飞进云里时差别明显。

10. 玩法查询与飞控

FCLCloudField::Density 和 Sdf 在 CPU 上三线性采样同一份建模数据和 SDF（按当前的表示），供结冰（密度 > 0.04 时每秒积冰 0.55 × 密度，满 1 失速）、检查环净空检查和 HUD 读数使用。切到 2.5D 包络后，隧道在玩法上也被填实。

飞控是鼠标瞄准式：鼠标给出世界方向，飞机按航向误差压坡度（上限 70°，陡爬升时减小），坡度决定协调转弯的转弯速率 1.5 × g × tan(φ) / v，俯仰误差单独换算成爬升或下降速率，再按当前坡度分解成机身的俯仰和偏航角速度。瞄准方向最多领先机头 75°，失速时机头降到 30° 下滑。

UE 的 FQuat(Forward, +a) 是把右翼抬起来（向左滚）。横滚角速度符号弄反时，飞机会稳定在倒飞状态，而且照样能飞完赛道。所以自测必须检查机身朝向，不能只看有没有过环。

11. 测量与自测

Tools/iterate.ps1 编译后在屏幕外（-RenderOffScreen）运行脚本化的自测，固定 60 帧步长（-benchmark -fps=60），写 Saved/Capture/results.txt 和截图。检查项：云景生成、SDF 不越界、隧道在两种表示下的密度、检查环净空、结冰、自动驾驶全程正飞过 13 个环、模拟鼠标操作（爬升、急转、俯冲、按住 A）。性能块对 10 种配置 × 3 个视点，各取 30 帧平均的 GPU 耗时。

RTX 3060、1600×900 下的典型值（与后台负载有关，只看相对大小）：远眺 1.7 ms，云塔之间 2.6 ms，隧道内 5.6 ms；隧道内改全分辨率约 21.6 ms；光照网格每帧 4 层约 0.5–0.9 ms。

12. 坑点清单

  1. BC1/BC4 的“保守”依赖具体解码器。只按理想公式编码，NVIDIA 上会越界；要按各厂商插值的上界编码。
  2. 一维距离变换用 float 和小的无穷大会溢出；用 double，无穷大 1e12。
  3. BC 三维纹理的上传行距和层距按块算，不按纹素算。
  4. 噪声按相机相对坐标采样会随镜头滑动；必须用世界（域）坐标加风偏移。
  5. 透射率截止后不当作完全不透明，太阳圆盘会从厚云后透出来。
  6. 调试热图（循环次数、采样数）不能走两档拆分，否则一条光线被拆成两半计数；还要乘 View.PreExposure，否则手动曝光下整片过曝。
  7. 光照网格只算云内格子时，洞壁会发亮（插值到云外的 0）。
  8. 多重散射近似项太强时，隧道内壁冲成一片灰白；前向相位瓣太强时，朝太阳看隧道会冲白。
  9. UE 体积云不加 Volumetric Advanced 输出节点只有单次散射，背光云发灰。
  10. 近处密度衰减照搬讲座的 10–120 m，在 26 m 半径的隧道里洞壁会变成半透明的雾。
  11. 检查环材质的自发光超过约 5 时，橙色被色调映射冲成白色。
  12. 性能数字在共享桌面上可以差两三倍：同时开着安卓模拟器等程序时尤其明显，要多帧平均并交替测量。

13. 移植清单

  1. 复制 Source/CloudLabShaders（模块和 CLRender.h/.cpp）和 Shaders/CloudLab.usf，在 .uproject 里注册模块（加载阶段 PostConfigInit：全局着色器要在着色器映射建立之前注册）。
  2. 准备数据：用自己的建模工具导出 512×512×64（或任意尺寸，改 CLRender.h 的 NX/NY/NZ）的轮廓、类型、密度三通道；SDF 用 CLCloudField.cpp 的 SignedEdt 和 Encode 离线生成，正式项目只保留一种编码。
  3. 在游戏线程创建 FSceneViewExtensions::NewExtension<FCLCloudRenderer>(World)，调用 UploadVolumes 和 UploadNoise，每帧 SetFrame（太阳方向、颜色、风、域最小角）。
  4. 如果场景里已有 UE 的 Volumetric Cloud 或天空大气的云层，二选一，避免重复绘制。
  5. 按目标平台降档：调研报告第 13 章给出的手游高档是 1/8 至 1/16 屏幕面积的分辨率、步数上限 32 至 64、单张 64³ 噪声、只查光照网格并分 16 至 32 帧更新、不做二次折叠噪声；SDF 跳空在低步数预算下最关键，应保留。本工程没有在移动端实测。
  6. 玩法需要云密度时，CPU 端保留一份建模数据（或降采样版本）做查询，不要从 GPU 回读。
